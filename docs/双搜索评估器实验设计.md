# MCTS / Alpha-Beta 统一评估架构

## 1. 设计原则

模型表达棋盘和着法，搜索器决定如何使用模型。模型不得依赖某个搜索器的候选集合，
也不应为 MCTS 和 Alpha-Beta 输出两个不同的局面价值。

```text
棋盘增量状态
├── value(state)            唯一 WDL，纯棋盘函数
└── move_logit(state, move) 单着未归一化分数

MCTS        = value + 所有候选 move_logit + softmax
Alpha-Beta  = value + 按需 move_logit 排序
```

两种搜索的蒸馏发生在训练数据层：MCTS 访问分布、Alpha-Beta 精确值/上下界、最终胜负
共同监督同一个模型，而不是让两个 Value 头互相模仿。

## 2. v13 当前结构

### 2.1 唯一候选无关 Value

`evaluate_value(board)` 只执行：

1. 读取当前执棋方的增量 accumulator；
2. ReLU + RMSNorm；
3. `hidden → 96 → 96 → WDL3`；
4. 返回 `P(win) - P(loss)`。

它不执行候选生成、四轴候选扫描、Policy logit、softmax 或候选池化。完整
`evaluate(board)` 调用完全相同的 Value 计算，所以同一棋盘只有一个价值语义。

### 2.2 可延迟 Policy

`evaluate_move_logit(board, move)` 只为指定合法着计算：

```text
global hidden · position weights
+ four-axis local pattern · local weights
+ position bias
```

完整 MCTS Policy 对全部候选调用同样的单着公式后 softmax。测试验证单着 logit 差值
与批量 Policy 概率比严格一致。未来 PVS 可先使用战术等级、TT、killer/history，仅在
需要时计算神经 move logit，无需 softmax。

### 2.3 训练

模型只有两项核心损失：

```text
L = L_policy(MCTS/AB 着法目标) + L_value(最终 WDL/可靠搜索目标)
```

当前训练仍使用自博弈 Policy 和最终胜负。后续加入 Alpha-Beta 数据时：

- exact value 可监督 WDL；
- lower/upper bound 使用单边损失；
- PV 与已验证着法对使用排序损失；
- 未完整搜索的着法不能当负样本；
- MCTS/AB 分歧局面进入追加计算队列。

## 3. 为什么删除 v11 双头实验

v11 曾用 Rich Value 与 Fast Value 双头验证候选无关路径的速度，得到约 4× 加速。
实验说明拆分计算有价值，但双头会产生两个局面语义、内部蒸馏和梯度干扰，因此没有
保留。v12 直接让候选无关 Value 成为唯一正式 Value；v13 在这一语义上加入全棋盘
局部 pattern 增量汇总，旧模型不迁移。

## 4. 当前性能指标

使用 `az-value-bench` 比较完整 Policy+Value 和单独 Value：

```bash
cargo run --release -- az-value-bench model.safetensors \
  --iterations 100000 h8 h9 i8 g8 i9
```

第一阶段硬门槛：

| 指标 | 门槛 |
|---|---:|
| Value 不调用候选生成 | 必须 |
| 增量状态与重建状态误差 | ≤ 1e-5 |
| 单着 logit 与批量 Policy 一致 | ≤ 1e-5 |
| Value 相对完整 Policy+Value 加速 | ≥ 3× |
| Value CPU 吞吐 | ≥ 500k eval/s/核 |

2026-08-01 在 Apple Silicon、release/Fat LTO、hidden=192 的 v12 随机初始化结构基准：

| 局面手数 | Policy+Value eval/s | Value eval/s | 加速比 |
|---:|---:|---:|---:|
| 5 | 128,552 | 488,113 | 3.80× |
| 10 | 118,354 | 501,832 | 4.24× |

两个局面均超过 3× 解耦门槛；10 手局面达到 500k 目标，5 手局面低约 2.4%。当前仍是
浮点 Value 塔，后续 codebook 定点化和 SIMD 优化应继续提高吞吐。随机初始化只用于
测计算结构，不代表精度或棋力。

回放集检查命令：

```bash
cargo run --release -- az-value-eval model.safetensors data/replay.jsonl --limit 10000
```

因为完整入口与单独入口使用同一 Value，`entrypoint mae` 必须接近零；其余核心指标是
Value 相对最终结果的 MAE、校准、符号正确率以及实际 Arena Elo。

## 5. v13 全棋盘局部增量编码

v13 将 Policy 已使用的四轴 pattern codebook 同时用于 Value。根节点从黑白双视角扫描
全盘各交叉点的四条轴线，保存轴特征均值；落子后只更新穿过落子点、半径 4 内真正
发生变化的轴 pattern：

```rust
struct EvalState {
    global_black: Vec<i32>,
    global_white: Vec<i32>,
    local_black: Vec<f32>,
    local_white: Vec<f32>,
    move_count: u16,
}
```

落子只更新穿过该格的四条线及固定半径窗口：

```text
state' = state - old_pattern_features + new_pattern_features
```

Value 使用可加减的轴均值，不使用难以增量维护的全局 max。Policy 的单着特征仍保留
四轴 mean/max，两者共享同一个 `local_axis_embedding`，因此 WDL 与着法排序共同训练
棋形表示。

最初原型为维持每个交叉点的四轴 max，一次更新需要重算大量无关轴，只有约
194k–217k updates/s。删除 Value max 并按受影响轴更新后达到：

| 局面手数 | Policy+Value eval/s | Value eval/s | accumulator updates/s | Value 加速比 |
|---:|---:|---:|---:|---:|
| 5 | 130,081 | 492,575 | 763,410 | 3.79× |
| 10 | 118,792 | 488,068 | 826,687 | 4.11× |

同机随机 v13 模型在 10 手局面、每次 3000 simulations、重复 10 次时达到约
68,013 MCTS simulations/s。随机模型只用于计算结构基准，不代表棋力。

增量与整盘重建的黑白局部状态误差小于 `1e-6`，八种旋转/镜像下局部汇总一致。
下一步不是继续增加兼容层，而是根据真实 v13 训练结果决定是否把 pattern feature 从
2 维扩大，并将 codebook/accumulator 定点化与 SIMD 化。

## 6. 搜索实施顺序

1. 完成共享局部 pattern 增量状态和落子/撤销一致性测试。
2. 测量浮点与定点/SIMD Value 吞吐及训练精度。
3. 实现战术候选层，保证成五、防五等强制着不被裁剪。
4. 实现无激进剪枝的 Negamax、迭代加深、PVS、置换表和时间控制。
5. 使用 `move_logit`、TT、killer/history 做着法排序。
6. 建立 MCTS/PVS/Hybrid 统一 SearchResult 和 Arena。
7. 收集双方分歧局面，相互提供训练标签。
8. 最后逐项实验 LMR、futility、razoring；每项必须单独消融。

## 7. 最终评估

- 固定战术集：成五、防五、VCF、唯一防守、长强制线；
- Value：WDL 交叉熵、Brier score、校准曲线；
- Policy：Top-1/Top-3、唯一防守召回、AB 首着 cutoff 率；
- 性能：Value eval/s、move_logit/s、TT 命中率、有效分支因子；
- 棋力：相同时间下 MCTS、PVS、Hybrid 成对开局 Elo 与置信区间。

任何架构变化首先服从统一语义和增量计算，不再以兼容旧模型为设计目标。

## 10. 成五威胁静态搜索

PVS 叶节点增加独立 `threat_extension_depth`，默认 8。它只沿以下确定性变化继续：

```text
当前方有立即成五点 → 返回可证明胜值
对方下一手有成五点 → 只搜索必须防守点
没有直接成五威胁 → 立即调用唯一 WDL
```

这使主搜索深度 1 也能证明“做开放四、对方堵一端、另一端成五”的三手胜，测试局面
返回 `value=9997`，仅使用 94 个节点，其中 7 个威胁节点。关闭延伸时同一深度不会
返回 mate 分数。

初版在每个叶节点扫描全部候选，使普通局面速度从约 153k 降到 97k nodes/s。优化后
先检查最后一手的固定局部窗口；只有它确实制造立即成五威胁时才进入完整强制着生成。
优化后的相同普通局面结果：

```text
预算          100,000 nodes
完成深度      4
速度          165,551 nodes/s
威胁节点      3,309
TT 命中       479
beta cutoff   6,054
```

命令可用 `--threat-depth 0` 做消融，或调整默认的 8 层上限。当前延伸不包含活三、眠三、
双三等非直接成五威胁；这些需要下一阶段独立的威胁类别与防点生成，不能混入本轮安全
静态搜索。

## 11. 在线 PVS → MCTS 引导

自博弈现已支持概率调用浅层 PVS，但不把 PVS 输出直接写成 Policy 标签。每个局面的流程为：

```text
按概率触发 PVS
  ├─ 完成指定深度：最佳着的 MCTS 根先验乘以 boost 后重新归一化
  ├─ 证明当前方必胜：最佳着根先验强制为 1
  └─ 节点预算耗尽且无证明：丢弃结果
随后照常运行 MCTS
训练 Policy 标签始终只取最终 visit distribution
```

这种结构把 Alpha-Beta 当成稀疏战术教师：它能引导 MCTS 把预算投向战术着，但不能用单一
PV 覆盖整张策略分布。默认参数先采用小比例、小预算，便于本机消融：

```toml
selfplay_pvs_probability = 0.05
selfplay_pvs_depth = 4
selfplay_pvs_threat_depth = 10
selfplay_pvs_prior_boost = 2.0
```

TensorBoard 新增 `hybrid/pvs_call_rate`、`pvs_completion_rate`、`pvs_proven_win_rate`、
`pvs_mcts_top1_agreement` 和 `pvs_hint_average_rank`。首轮主要观察调用后的 MCTS 一致率、
提示着平均排名以及 selfplay samples/s；之后再用相同随机种子比较 `probability=0` 与
`0.05` 的 Arena 胜率。若一致率低且 Arena 无增益，应先降低 boost，而不是提高 PVS 覆盖率。

最新权重下进一步比较了不设节点上限的完整深度搜索。深度 4 在测试局面约需
`0.06–0.24s`；深度 5 在普通中盘约需 `0.13–0.54s`，但仅落一手的高分支局面达到
455,285 节点和 `2.56s`。因此自博弈顾问取消节点数截断，避免产生大量“未完成深度”的
含混结果，默认改为完整深度 4、威胁延伸 10。深度 5 暂不全局启用，后续应按棋局阶段或
战术触发升级深度，以控制早期局面的耗时长尾。

## 12. 可撤销搜索局面 M1

PVS 主搜索与威胁延伸已改用单个 `SearchPosition` 做原地 `make/undo`，棋盘不再为每个
子节点复制。第一次实现同时反向重算局部神经摘要，实测反而慢约 10%～20%，因此没有
保留该方案；当前采用棋盘原地撤销、评估 accumulator 快照栈，确保撤销为低成本恢复。

最新权重的五手基准保持完全相同的最佳着、Value、节点数和 PV：深度 4 为 27,406 节点、
`0.234s`，深度 5 为 75,662 节点、`0.539s`。相比改造前约 `0.244s/0.541s`，目前只是
消除了棋盘复制并获得小幅改善。下一步不能继续依赖完整 accumulator 快照，而应在落子时
生成一次局部特征 delta 并压入栈，撤销时直接减去 delta；随后再处理候选集合和威胁状态
的增量维护。

后续实验发现浮点 delta 反向相减会在大量分支间积累舍入误差，并改变 PVS 零窗口边界，
因此最终改为按最大 ply 预分配 accumulator 栈，每层使用 `clone_from` 写入复用缓冲区，
撤销只回退栈指针。这样既无每节点分配，也能逐位恢复父状态。

候选点同时改为增量邻域计数，make/undo 只更新落点半径 3 内的计数；普通 PVS 与强制着
检测共享同一份候选列表，不再重复扫描棋盘。最新基准保持搜索结果完全一致：五手局面
深度 4 从约 `0.244s` 降至 `0.221s`，深度 5 从约 `0.541s` 降至 `0.520s`；仅落一手的
高分支深度 5 为 455,284 节点、`2.548s`、约 179k nodes/s。固定数组 TT 也做过实验，
当前容量下碰撞改变节点数且没有速度收益，已回退。下一主要热点是每节点的全候选
`would_win` 扫描，应由增量四方向威胁表替代。

增量成五威胁表现已完成。状态为双方每个空点的四方向成五标记；make/undo 只重算穿过
变化点的对应方向，强制着生成、必须防守、着法排序和威胁静态搜索触发均读取缓存。
逐步走子测试会把缓存与全量 `would_win` 逐点对照。最新权重保持最佳着、Value、节点数
和 PV 完全一致，五手深度 5 从 `0.520s` 降至 `0.404s`（约 187k nodes/s），一手高分支
深度 5 从 `2.548s` 降至 `2.371s`（约 192k nodes/s）。下一阶段将在同一四方向状态上扩展
活四、冲四和活三分类，作为严格 VCF 的强制着生成基础。

## 13. 从搜索提示转为训练闭环

此前 PVS 证明只影响当前一步 MCTS，之后被丢弃，无法让下一代模型吸收。Replay 现增加
可选 `TacticalTarget`，保存当前方严格证明胜负、mate 距离、强制着和完成深度，并在棋盘
对称增强时同步变换强制着。严格必胜样本训练时使用：

```text
Policy target = 0.5 × MCTS visits + 0.5 × PVS forcing policy
Value target  = 最终终局 WDL
```

未证明的 PVS 分数不进入标签，严格必败暂只记录、不蒸馏着法，避免把“所有着都输”时的
偶然抵抗着误当最佳策略。新增 `hybrid/tactical_target_rate` 和证明负率，用于决定后续难例
重采样强度。这使流程首次形成最短闭环：自博弈暴露局面、PVS 给出严格证明、Replay 保存、
下一次训练吸收、EMA 模型继续产生新局面。后续 Tactical Head 是增强该闭环，而不是闭环
成立的前置条件。

实际闭环前 6 个 update 显示：最新严格证明占全部局面约 1.79%，而 PVS/MCTS Top1
一致率 36.06%，几乎恰好等于 PVS 调用中的证明胜负比例 36.03%；未证明 PVS 着平均仅排
MCTS 第 8.3。因此策略调整为：只有严格证明胜可以硬覆盖根先验；证明负只写 Replay；
完成深度但未证明的结果不再修改 MCTS，仅记录独立的 Top1 一致率和平均排名。这避免把
未标定的浅层 PVS 静态判断注入自博弈，同时保留其作为难例发现器的价值。
